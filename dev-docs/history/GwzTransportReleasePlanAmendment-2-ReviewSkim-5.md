**New issues (obvious only):**

**P2-6** · amendment TR1.8 "Precedence of the credential helpers" (line 163) and OD16's precedence bullet (line 364) · The new text has a helper with a credential for the URL "answer the challenge" first, for every challenge, and "otherwise … answers `Negotiate` or `NTLM` through SSPI with the helper's identity". 1.0.17 never consults a helper for a challenge that offers only `Negotiate`: `parse_unauthorized_response` sets only `GIT_CREDENTIAL_DEFAULT` for `Negotiate` (`winhttp.c:624-627`), and only `NTLM`, `Basic` and `Digest` add `USERPASS_PLAINTEXT` (`:618-622, 629-637`), so the callback's helper branch (`transport_support.rs:265-271`, gated on `is_user_pass_plaintext()`) is skipped and `Cred::default()` answers. A Negotiate-only intranet server with a stale password in the user's credential store authenticates on 1.0.17 through the logon session and, under the new text, gets the stale password from the helper (a failed login, or a locked account after retries). The text also prefers `Basic` when offered, where WinHTTP applies a helper's user and password over `Negotiate`, then `NTLM`, then `Digest`, then `Basic` (`winhttp.c:139-147`). *Fix:* the precedence bullet reads "When the challenge offers `NTLM`, `Basic` or `Digest`, a configured credential helper (TR1.6), `gh` among them, with a credential for the URL the credential will be sent to answers first, over the scheme WinHTTP would pick for a user and password: `Negotiate`, then `NTLM`, then `Digest`, then `Basic` (`winhttp.c:139-147`), through SSPI with the helper's identity for the first two. A challenge offering only `Negotiate` takes the logon session's default credentials, and no helper is asked (`winhttp.c:624-627`)." OD16's precedence bullet says the same in short, and the fixture gains a `Negotiate`-only row with a helper credential present, asserting the helper is not asked and the logon session authenticates.

**P3-4** · amendment §3.19 line 468 · "the transport design's §11 HTTPS cell, whose 'other helpers rejected' reads 'configured helpers, as git2 runs them'" contradicts the adopted mechanism, under which git runs them through `git credential fill`. *Fix:* "configured helpers, through `git credential fill` (TR1.6)".

**P3-5** · amendment §3.19 line 491, amendment 1's §3.8 notes item · The replacement text still carries the superseded rule: "that the transport signs RSA with SHA-1 only for a server that offers no SHA-2 RSA algorithm, as 1.0.17 does", so S7.2's migration notes would state it. *Fix:* "that the transport signs RSA with SHA-1 exactly where libssh2 does, in TR2.8's three cases, as 1.0.17 does".
