## Operator decision (2026-10-11), controlling

- **D5 (b), the Pageant confirmation wait.** In 1.1.0 the wait stays in the SSH clock's Network phase: the stall and aggregate clocks keep running. There is no LocalInteraction classification and no clock extension owed to step 3.6. The cost is stated plainly in the design, L20, section 14 item 13, the guide and the plan: a Pageant set to confirm every use, whose prompt outlasts the stall, fails that attempt (raise `--ssh-timeout`, or `--transport native`, which waits as 1.0.17 did), and a passphrase entered on first use succeeds on retry. The same holds for ssh-agent confirmation (`ssh-add -c`) on macOS and Linux today. **Nothing in the accepted `GwzTransportSshHelperClockAmendment.md` changes** (it is not edited), and this is the branch Consistency N1 named as "state the Network-phase reading". Option (a), an amendment admitting Pageant into the clock's local phases, was not taken. Recorded as D5 in `GwzTransportTR18-OperatorDecisions.md:39`.
