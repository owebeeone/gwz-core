# SSPI worker creation-time containment feasibility

**Nonnormative targeted addendum, 2026-10-03. No implementation, design approval, or product GO.** `PROC_THREAD_ATTRIBUTE_JOB_LIST` worked together with an explicit IPC handle allowlist on the actual Windows 11/OpenSSH launch shape. It closes the investigated parent-loss window between creating a child and assigning it to a Job: the child was already a Job member when `CreateProcessW` returned. This supersedes the earlier primitive experiment's suspended-then-separately-assigned launch sequence for the creation-containment question.

Microsoft documents Job-list values as Job handles assigned to the child in their specified order, supported from Windows 10 and Windows Server 2016. The handle-list attribute permits only the supplied inheritable handles and requires `bInheritHandles=TRUE`. Attribute values must remain valid until the attribute list is destroyed. The fixture retained both arrays through process creation and list deletion. [UpdateProcThreadAttribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute).

The fixture used the two-call attribute-list allocation pattern, `STARTUPINFOEXW`, `EXTENDED_STARTUPINFO_PRESENT`, and an explicit executable path. Its Job-list array contained one unnamed, parent-owned Job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; the handle-list array contained only stdin/stdout/stderr pipe ends. `GetHandleInformation` confirmed the Job handle was not inheritable. No breakaway flag was supplied. There is no separately callable Job-assignment path in the fixture. [InitializeProcThreadAttributeList](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-initializeprocthreadattributelist), [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

Exit was confirmed by waiting on held process handles, not by inferring it from a termination request or a missing PID. These are individual observed timings, not an absolute kernel termination deadline.
