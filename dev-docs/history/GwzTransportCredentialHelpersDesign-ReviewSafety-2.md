## 1. Findings

### [P3-6] M6 and M9 put server-chosen text into gwz's own sentence, unattributed, against the messages' own rule

- **Root cause.** New in the changed range. M9 (line 305) inserts the 403 status line's reason phrase, "printable ASCII cut at 64 characters", and M6 (line 301) the challenge's scheme names, "at most four, each an HTTP token cut at 32 characters", into prose that speaks as gwz. Both are chosen by the server, and M6's by any HTTPS server a member reaches, credential or not. The messages' rule two paragraphs earlier (line 293) says they "name no URL, host, body or helper output"; a URL fits in 64 printable characters, and an HTTP token admits `.` and `-`, so `visit-evil.example-now` is a valid scheme name.
- **Location.** §11 lines 293, 301, 305; §10 fixture line 244 ("a 403 with a reason phrase"), T8(b), T10(b); T12 (redaction) does not cover server text.
- **Violated invariant.** Line 293's rule; HTTPS:304-305, which retains sanitized status and "never … arbitrary headers". The reason phrase is free text on the status line, not the status.
- **Reproduction.** Fixture 403 with status line `HTTP/1.1 403 Forbidden - visit evil.example/x to continue`: M9 reads "The server refused this account (HTTP 403 Forbidden - visit evil.example/x to continue) after gwz sent your credential helper's credential…", on the terminal, in `--json`'s `errors` and in gwz-py's `member_errors` (line 291). Fixture 401 with `WWW-Authenticate: Visit-evil.example-now`: M6 reads "The server asks for HTTPS authentication by Visit-evil.example-now, which gwz does not answer here…". No control character survives either filter, so no terminal escape; the text is bounded, but unattributed.
- **Impact.** A social-engineering channel through trusted output; low and bounded. Non-blocking.
- **Required correction.** Attribute and delimit the server's words in both messages (for example `the server's reason: "<phrase>"`, `the schemes the server named: "<token>", …`), or drop `<reason>` from M9, which already sends the user to `git ls-remote` for the server's own explanation; keep the length cuts.
- **Closure test.** T8(b) and T10(b) gain a reason phrase and a scheme token shaped as instructions; assert each appears only inside the delimiters, cut at 64 and 32, and that line 293's rule is restated to allow exactly those two attributed fragments.

## 2. Invariant analysis, with the changed range

**New architectural root cause: none.** The admission change (E6, E9) re-assigns two waits from the interaction budget to the existing allocation budget; the completion rule (E8) changes the lookup's join condition; the latch condition (E7) narrows an existing rule. None adds a component, shared state, or a cross-endpoint dependency: in 1.1.0 each command or gwz-py operation still has its own runtime and its own `HelperSlots` (`cancellable.rs:147-148`, `local_command.rs:23`). P3-6 is a message-shape defect.

The twelve deviations the drafter lists were analysed through the diff's eight hunks rather than a separate list. Those the lane owner named:

1. **M6 without a hint.** Verified: with no scheme libgit2 serves, 1.0.17's native path refuses ("server requires authentication that we do not support", `http.c:184-187`); on Windows WinHTTP admits only NTLM, Negotiate, Basic and Digest (`winhttp.c:617-640`), which TR1.8 covers. M6 is reached with no credential sent. No hazard; the only defect is P3-6's text.
2. **M7 names a Rust API only.** Verified by the grep above: `Disabled` is built only by gwz-core's own tests; the CLI and gwz-py never build one, so M7 reaches no CLI or Python user. The fail-closed path (`transport_binding.rs:106-113`, anonymous policy, no spawn) is unchanged.
3. **M9's status and reason phrase.** P3-6. The body stays out, as HTTPS:330-331 requires, and the text says so.
4. **stderr's zeroizing scratch buffer.** Closes P3-4. See R-B on the pipe.
5. **Slots awaited within the allocation deadline; `Capacity` folded into M10.** The allocation deadline is one budget for the 64 request slots, the pool checkout, the helper permits and the host slots, and the authenticated retry inherits what the anonymous attempt left (`TH/https_endpoint.rs:216-226`, `Retry { budget }`). In 1.1.0's shape the anonymous attempt consumes milliseconds of it (eight members per host under a 32-per-host cap), so a queued member in practice gets the full 30 s; `<m>` can overstate only by that (R-C). M10 never latches, so a slow user can never hide a working helper. Under OQ3 (a)/(b) with more than eight prompting members, members beyond eight fail with M10 at 30 s on every run until a credential is stored through git, which M10, N6 and §8 line 183 state. No new stuck state: every wait ends at 30 s or 120 s, and T18 covers the retained-children case that produced today's immediate `Capacity`.
6. **Clone's quiet skip of M2, M3, M7 and M9.** Every `gwz clone` sets `skip_private_access` (`clone_workspace.rs:193`); the branch removes the directory, forgets the member's transport row and returns `Ok(None)` (`apply.rs:68-84`, `transport_observations.rs:42-50`), as `clone.md:65-70` documents ("no member progress, response row or transport diagnostic"). So a rejected (M3) or forbidden (M9) credential on clone leaves no trace where 1.0.17 failed loudly (its replay-limit message is not among `clone_error`'s refusal forms, `transport.rs:742-751`). This conceals a credential problem; it exposes nothing. It follows the documented contract and 1.0.17's own quiet skip of M2 and M7, D19 and N14 state the difference, and the loud outcomes stay loud because their codes are not `remote_rejected` (T8(c) asserts M1). Not a finding; R-D.

## 3. Risks and next action

- **R-A.** Under OQ1 (b), name the Open field that carries the username and define it as the percent-encoded form; the endpoint's re-validation (DES §3.3, "again at the endpoint") must include D18's decoded check on it. One sentence when (b) is chosen.
- **R-B.** "The stderr reader is then abandoned, within the same bound" should say whether the read end stays open until the bound or closes at completion; a helper's background child that writes to stderr after the close receives EPIPE/SIGPIPE, as with any parent closing a pipe. 1.0.17 held it open forever, so neither reading is worse.
