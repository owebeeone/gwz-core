## 2. Invariant analysis

- **"No fallback after an open" / "chosen before any connection opens".** Holds for the Pageant-window route (`FindWindow` before the open), the OpenSSH default pipe, TR1.6's helper-name route and OD11's key listing. It is structurally unsatisfiable for WinHTTP default credentials, whose only signal is the 401 challenge (P2-1). The Pageant race (a window appearing after the decision) is a bounded time-of-check window whose failure is a refusal (`Authentication`), not a wrong credential or a silent fallback; the native path has the mirror window; not a finding.
- **OD13 parity, "a Windows configuration that works on 1.0.17 keeps working".** Verified to hold where 1.0.17 itself fails or the route exists: no agent reachable (1.0.17's callback offers only the agent — no key-file fallback — so both refuse); the mingw/MSYS socket form (libssh2 undefines `PF_UNIX` on Win32, so 1.0.17 never spoke it); Pageant visible (routed); `SSH_AUTH_SOCK` unset with the OpenSSH service (both use `\\.\pipe\openssh-ssh-agent`). It fails as written for `HOME` unset (P2-5), SSO servers (P2-1) and environment proxies (P3-1). schannel trust and revocation: WinHTTP and native-tls/schannel both use the machine store and both leave revocation checking off by default; plausible parity, unverified by any row — S5.6's "TLS and proxy parity" cell already demands evidence. `gh.exe` with spaces, the helper forms and the off switch's three forms are in TR1.8's list.
- **The switch split.** The session host crates and `pub mod session_host` are already ordinary code, reviewed at their gates and uncalled; that is fine. The second switch's lifecycle is not: it exists too late for rule (e) (P2-3) and S7.1 (1.1.0) cannot prove it was applied (P2-4).
- **OD14, gwz-py on the native path.** False as composed with S7.1 (1.1.0): the binding's host-context-less SSH branch is the transport (P1-1); the retained Python assertions would confirm the leak (P2-2). With P1-1 fixed, the selection mechanism (a host context installed only by `with_local_transport`) keeps gwz-py native with no further code.
- **Rule (e) and main's releasability.** Under the one-review-per-phase ruling, "its own review" is the phase review; ordinary-path session changes can reach 1.1.0 only after that review and the checkpoint's (d) listing; rule (c) still forces Surface for documented-contract changes. Rule (b) is unchanged. The stuck state is P2-3's, not rule (e)'s wording.
- **Publishing.** The fork crates' `publish = false` at bootstrap placeholders and the four unregistered names are as the amendment states; the lockstep gate already counts 18 crates, so TR3.3's "as it publishes the others" holds mechanically; the first-publish token path is the gap (P3-5). The Phase 10 stop rule bounds a mid-run failure to a burned version; the Windows leg's non-gating (P3-3) makes that burn likelier for this release. gwz-py's `=1.1.0` pin and its Windows wheel (`publish.yml` builds on `windows-2022`) are consistent; S7.3's dabeest extension build is the pre-publish proof.
- **Performance.** TR2.9's fixture criterion ("within 2D plus a fixed margin, not N × D") detects client-side serialization; it should be stated against an N-independent bound at two values of N so that D cannot be chosen to pass. TR8.1 (1.1.0)'s live re-measure is the real proof. The miss path's end is undefined (P3-7). The unreported alpha rows (faster, 8 connections) are consistent with the two named causes — the queued opens never reuse an idle connection — and do not indicate a third.
- **Evidence and disclosure.** The amendment's text discloses nothing beyond what the plan already carries (dabeest, the public set). The scratch logs hold an agent socket path and would need §2's redaction if ever filed; the text says they will not be. TR1.8's and TR8.4's live rows carry the go rule.
