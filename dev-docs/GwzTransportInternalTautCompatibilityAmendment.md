# GWZ transport — internal Taut compatibility amendment

Date: 2026-09-24. Status: **DRAFT operator clarification for review; no implementation or activation**.

The operator confirmed that GWZ transport Taut messages are currently internal and have no other clients. This narrows the compatibility scope of the accepted [sequenced requirements](GwzTransportSequencedStreamRequirements.md) and [design](GwzTransportSequencedStreamDesign.md) for the planned profile-3 implementation. It does not change message ordering, endpoint authority, Git behavior or the future-carrier boundary.

**C1 — Lockstep projections.** The Taut schema and generated Rust/Python projections may change together. The new implementation does not owe byte-for-byte compatibility with previously serialized transport messages, acceptance by old generated readers, or old-core/new-driver interoperation. Do not hand-edit generated code or create a shadow protocol.

**C2 — Functional regression.** While the current internal profile-1/2 paths remain in use, they must still perform their current operations correctly after regeneration. This is a functional regression gate, not a retained-reader or encoded-byte compatibility gate. A profile mismatch must still refuse before Git, credential or pool effects; a profile-3-only Bind must not silently downgrade. These are current-session safety rules, not a promise to support independently deployed old clients. Receiver-generation pinning, unsupported-capability refusal, malformed-message rejection and bounded-resource checks remain required.

**C3 — Field shape.** `Envelope.message_seq` remains optional at the Taut shape because bootstrap and current profile-1/2 messages do not carry a sequence value. The generator may encode its absent value as null; no legacy-reader qualification or wrapper solely to preserve old bytes is required. Profile-3 positive-stream frames must carry a positive sequence and pass current encoding, decoding and bounded-validation tests.

**Precedence.** For this profile-3 work, C1–C3 supersede [sequenced requirements](GwzTransportSequencedStreamRequirements.md) Q8's unchanged profile-1/2 *encodings* clause and [sequenced design](GwzTransportSequencedStreamDesign.md) §5's retained-reader/old-projection qualification. They also supersede the old-reader and old-byte gates in [placement design](GwzRemoteTransportPlacementDesign.md) §3 ("retained old readers", "wire compatibility is tested"), §6 ("old v1 serialized fixtures and retained Rust/Python decoders"), §8 (old/new core/driver combinations solely as a reader-compatibility matrix), and §9 ("preserves v1 wire meanings") **only as prerequisites for adding profile 3**. The historical placement acceptance and existing profile-1/2 functional semantics remain intact. No physical wire-carrier qualification is introduced.
