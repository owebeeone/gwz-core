## Blind convergence

The three reviewers were blind to each other, so findings that more than one of them reached independently are the highest-confidence result:

- **C P2-1 = S P2-1 = T P2-1 (all three).** A fair refused test has `hi = N`, which §4.4 classes as "inconclusive". The test therefore re-runs with no backoff, and the machine's "test refused" edges can never fire.
- **C P2-2 = S P2-2 = T P2-2 (all three).** The Suspect confirmation takes `k` from the wave's `hi`, and "fill up to `k − 1`" then re-creates the refused wave. In the Suspect case (always the case for SSH) members fail on budget, and `N` is never learned.
- **C P3-1 = S P3-7.** The §4.6 edge labels set `N := Connected`, which can lower `N` on a success.
- **C P3-4 = S P3-1 = T P3-2.** `N_before` names the most recent Overload instead of the earliest in the run, and the restore can land in STABLE at `C`.
- **S P2-5 = T P3-3.** A due test can be starved by churn, because nothing drives the key to quiet.
- **C P2-3, C P2-4 and S P2-4.** §5.5's "per member" bound is false, and resetting the key's backoff when its queue empties gives each member a fresh budget against a dead host (the retry plan's `--jobs 1` rationale).
- **C P2-5 and S P3-6.** The requeue of a discovery 429, and the change of classification, contradict the retry plan, OD18 and the HTTPS design, and the document does not say so.
