## 1. Findings

### [P2-6] OD16's recommended shape routes into the native path's default-credential offer on any host that challenges, with no zone bound and no disclosure of that effect
**Location.** §3.14 OD16 ("No credential has been offered, and the request changed nothing on the server"); §3.5 TR1.8 "The one route chosen after an open (OD16)"; §3.2's new row; OD13's parity bullet. Code: `winhttp.c:1000-1050` (callback before the zone-checked fallback), `:230-282` (libgit2's own zone bound, which gwz's callback bypasses), `:184-212` (autologon policy LOW), `transport_support.rs:272-274` (`Cred::default()` whenever offered).
**Violated invariant.** The program's own rule for the forced-authentication class (amendment 1 §2 item 3 and §3.4: a remote pipe name is refused before any open because the open itself sends a NetNTLMv2 response); a bounded exception must state what it bounds; "never worse than 1.0.17" is met, but the text claims more than it delivers.
**Sequence.** A Windows user fetches a workspace whose manifest names a member at `https://attacker.example/x.git` (a public manifest, a direnv-style config, or an agent-built command). Under (b): the transport sends the anonymous ref-advertisement request → the attacker answers `401` with `WWW-Authenticate: NTLM` → the trigger fires → the native route opens its own connection → libgit2's 401 handling calls gwz's callback → `Cred::default()` (no zone check, autologon LOW) → WinHTTP sends the logon session's NTLM response (NetNTLMv2, crackable offline or relayable) to the attacker's TLS-authenticated host. The first request offered nothing, as OD16 says; the route's purpose is that the second connection offers the logon credentials, and the trigger is the attacker's to send. 1.0.17 behaves the same today; the transport without this route (shape (a)) refuses and discloses nothing. OD16's text, which the operator adopts at acceptance, does not say so.
**Impact.** The operator is asked to adopt (b) on a safety claim that omits the hazard the route exists to reintroduce; if adopted as written, 1.1.0's transport route is only as safe as 1.0.17 against a hostile HTTPS remote on Windows, when it could be strictly safer at the cost of a bounded, disclosed parity exception.
**Remedy.** OD16 and TR1.8 state the effect ("the native route then offers the logon session's default credentials to that host") and bound the trigger: the route fires only when the URL maps to the Local Machine, Intranet or Trusted zone (`IInternetSecurityManager::MapUrlToZone`, the bound libgit2's own fallback applies) or when the host is explicitly configured; any other 401 `NTLM`/`Negotiate` is refused with a message naming the off switch, and the migration notes list it as the one parity exception of OD16. TR1.8's Safety finding list names this hazard and the bound. If the operator prefers unbounded parity with 1.0.17, OD16 records that choice with the hazard stated, so that it is a decision and not an omission.
**Closure test.** TR1.8's Negotiate fixture gains a second row: a loopback server whose name maps to the Internet zone answers `WWW-Authenticate: NTLM`; the 1.1.0 build refuses, the transport's record shows one anonymous request, the fixture records no second connection and no authentication exchange, and the message names the off switch. The intranet-zone row succeeds on the native route as before.

### [P3-9] TR2.12's "a candidate CI configuration that builds with both cfgs" does not say the transport-only configuration — 1.1.0's shape — stays beside it
**Location.** §3.5 TR2.12; §3.13 rule (a); the transport candidate job today builds one shape (`transport-candidate.yml`, `tests/transport_backend/prepare.py:65`).
**Consequence.** Read as replacing the existing job, every pre-activation build becomes "transport on, session on", and the composition 1.1.0 ships — transport on, session off — is first compiled at S7.1 (1.1.0), exactly when the inventory moves the placement projection that today's transport code references (`gitbackend.rs:217-225`) out from under the transport switch. **Closure test.** A workflow-text test that the candidate job has two legs until S7.1 (1.1.0): `--cfg gwz_transport_candidate` alone, and both cfgs.
