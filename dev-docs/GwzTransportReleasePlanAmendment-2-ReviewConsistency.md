### [P2-1] After S7.1 (1.1.0) ungates gwz-core's transport sites, a binding-less SSH operation — every gwz-py SSH operation — takes the transport's lazy endpoint, not the native path OD14 promises
**Location.** Object §3.10 S7.1 (1.1.0) ("removes `gwz_transport_candidate` from the transport's sites … in gwz-core and gwz-cli"); §3.1 outcome bullet and §3.2 row "gwz-py on the native path, with its behaviour and public API unchanged (OD14)"; §3.13 OD14. Code: `gwz-core/src/git/gitbackend/transport_support.rs:155` and `transport_binding.rs:36-48, 211-254`.
**Violated invariant.** A release outcome must be reachable by the steps the plan names; OD14 states gwz-py's behaviour is unchanged in 1.1.0.
**State sequence.** (1) S7.1 (1.1.0) removes the gate from gwz-core's 11 sites. (2) `remote_callbacks` now calls `configure` for every remote in the ordinary build. (3) gwz-py's dispatch runs a fetch through a `Git2Backend` whose `ssh` runtime has no host context (nothing in gwz-py installs one; the host context is installed only by gwz-cli's `with_local_transport`). (4) For an SSH URL, `configure` installs the smart transport; with `host_context()` `None`, the closure uses `runtime.endpoint()`, built from live `HOME`/`SSH_AUTH_SOCK` reads. gwz-py's SSH operations therefore run on the transport (pooled, 9 s stall clock, transport error texts, the `env::var_os` debt entry the session plan assigns to CS7.24), while its HTTPS operations stay native. The same applies to any other gwz-core embedder.
**Impact.** OD14's "behaviour and public API unchanged" is false as the steps are written; the reuse design's accepted recommendation 11 (refuse binding-less SSH), if a lane applies it at S7.1, would instead make every gwz-py SSH operation fail in 1.1.0. No S7.3 (1.1.0) row would catch either, because the object's S7.3 (1.1.0) asserts only CLI routes.
**Required correction.** Name the step (S7.1 (1.1.0) or a new Phase 2 step) that makes "no host context → native route, chosen before any connection opens" the rule for SSH as it already is for HTTPS, state how that reconciles with reuse-design decision 11 for 1.1.0 (the refusal is 1.2.0's, after CS7.24), add a Python row to S7.3 (1.1.0) asserting the native route on all three platforms, and add the row to S7.2 (1.1.0)'s ledger.
**Closure test.** On the activated 1.1.0 tree, a gwz-py SSH fetch against the disposable fixture reports no transport observation and the `connect()` record shows the connection opened by libssh2, not by `ssh_local::connect`; the same operation through the `gwz` CLI reports the transport route.
