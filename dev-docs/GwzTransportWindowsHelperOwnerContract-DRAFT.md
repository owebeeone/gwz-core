# GWZ transport on Windows: the credential-helper process owner (the WH2 contract, process half)

Date: 2026-10-10. Status: **DRAFT, step 4.1 of `GwzTransportWindowsParityPlan.md` (revision 3). Not reviewed; not frozen.** Step 4.1 asks for a dual Consistency plus Safety review (the contract handles credentials, `GwzWindowsHttpsIntegrationDesign-DRAFT.md:287`); this text does not freeze until that review has a GO and the operator has answered section 6. Step 4.2's implementation was written against it and changes with it.

Scope. This draft covers what a helper process owner must guarantee on Windows: process tree containment, timeouts, stdin and stdout framing, environment, cancellation, and exit reaping, each mapped to what the Unix owner (`src/git/endpoint/https_auth/`) guarantees today. It is the process half of WH2 (`GwzWindowsHttpsIntegrationDesign-DRAFT.md` §3 "WH2", §5). The path half (executable discovery, UTF-16 versus UTF-8 for the configuration view and paths, regular-file reads, quoting) is step 4.3's addendum to this contract and is listed in section 7 so that nothing is lost. Baseline row P08 (`GwzTransportWindowsBaseline.md:329`) executed the Job Object primitive; this contract is its composition with the owner. The Job Object stays private to the HTTPS helpers in core: not a second SSPI owner, not a public process library (`GwzWindowsHttpsIntegrationDesign-DRAFT.md`, §5).

## 1. The owner, in one paragraph

One helper child runs under one `Runner` (`runner.rs`), started by `process_tree::spawn` into a process tree the owner holds as a `ProcessTree`. A `HelperJob` (`owner.rs`) holds the child, the tree and the two admission permits (the host's helper slot and the endpoint's slot) from spawn to retirement. Success, failure, timeout, cancellation and a dropped future all end in one of three states: retired (tree empty, leader waited, permits released); retained (the `AuthOwner` keeps child, tree and permits until `reap_pending` or `reap_ready` finds both gone); or owner dropped (the retained children go with it). The interface is the same on both platforms; only `process_tree.rs` has two arms.

## 3. Timeouts and cancellation

Unchanged from Unix, and the Windows arm adds no clock. The lookup has an allocation allowance (waiting for a host slot), a single interaction deadline from the helper's start, and the caller's `CancellationToken` plus the owner's own. `Runner::check` is the one place that turns an expired deadline into `Timeout` and a cancelled token into `Cancelled`; success is admitted only if it still holds at the end, while the job still owns its tree (`finish_job`). `drained` polling is `DRAIN_POLL` (2 ms) inside the existing `CLEANUP_GRACE`; it is never a new deadline for the caller. A cancel or deadline before spawn starts no process (C1). A helper that outlives its grace is not a lookup failure on its own: it is reported as `CleanupPending` and stays charged to capacity.

## 4. Pipes and framing

Unchanged from Unix. Stdin: the request is written then the pipe is closed; a broken pipe is not a failure (Git ignores `SIGPIPE`; a helper may answer without reading), any other write error is `Pipe(kind)`. Stdout: at most `OUTPUT_LIMIT` (16 KiB) plus one probe byte; one more byte is `OutputTooLarge` and ends the tree. Stderr: drained and discarded without bound (a 40,000-byte flood does not reject the answer). The three run concurrently with the child's wait. Output is CRLF-tolerant by the existing parser (one trailing CR).

Windows-specific, drafted: (a) the pipes are the standard library's anonymous pipes, and `Command::spawn` holds one process-wide lock while it creates and inherits them, so no std-spawned child inherits another's ends; (b) credential bytes pass through the blocking pool's copy buffers, which this module cannot wipe: **OQ-C**.

## 5. Environment

The child's environment is exactly the captured snapshot (`Config.environment`) minus `GIT_ASKPASS`, `SSH_ASKPASS`, `GIT_DIR`, `GIT_COMMON_DIR` and `GIT_WORK_TREE`, plus `GIT_TERMINAL_PROMPT=0`; with a configuration view, also minus every `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_*` and `GIT_CONFIG_VALUE_*`, `GIT_CONFIG_SYSTEM` removed, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL` set to the platform's null source (`/dev/null`; `NUL` on Windows) and `GIT_CONFIG_PARAMETERS` set to the view. Nothing is read from the process environment (`runner/environment.rs` is the one place the platforms differ):

- **Names compare without regard to ASCII case on Windows.** `Git_AskPass` is `GIT_ASKPASS`, and a filter that missed it would hand an ask-pass program to the helper. A name that is not Unicode cannot match an ASCII name. Test: `askpass_is_never_in_the_helpers_environment` (with the mixed-case key on Windows); unit tests of `names` and `starts_with`.
- **Working directory.** Unix: `/`. Windows: the `SystemRoot` of the snapshot, which must be absolute; a snapshot without one is refused as `ConfigurationRefused`, and the lookup never falls back to the process's own directory (**OQ-E**).
- **The view is UTF-8 on Windows** and becomes a UTF-16 value without replacement; bytes that are not UTF-8 are `ConfigurationRefused`.
- **No size refusal on Windows.** On Unix an over-long environment value fails the spawn (`E2BIG`) and is reported as `ConfigurationRefused`. On dabeest `CreateProcess` accepted a 4 MiB `GIT_CONFIG_PARAMETERS` for a batch helper, so the Windows bound is the view's own `PREPARATION_LIMIT` (4 MiB) and nothing at spawn (**OQ-G**).
- **Creation flags**: `CREATE_SUSPENDED | CREATE_NO_WINDOW` (**OQ-D**). **Handle inheritance**: see C6(a) and **OQ-B**.

## 6. Open questions for the operator

Each has a recommendation; none is answered.

- **OQ-A: a helper that succeeded and left a descendant running.** Unix leaves it running (the owner forgets the group). Windows, as drafted, terminates it with the tree before releasing the helper's slot (C8). Options: (a) terminate (drafted: the tree is the unit of containment, and a Job Object has no "forget"); (b) clear `KILL_ON_JOB_CLOSE` on success and let it live, as Unix does. A credential helper that daemonizes (Unix `git credential-cache`) has no Windows counterpart in Git for Windows, whose helpers are `manager` and `store`. **Recommend (a)** and a line in the migration notes.
- **OQ-B: handle allowlist.** The plan's "allowlisted inherited pipe handles" needs `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`, which `std` offers only as unstable `raw_attribute` (issue 114854, unstable at Rust 1.95.0). Options: (a) accept std's behaviour: its spawn lock covers std-spawned children, and gwz opens no other inheritable handle in the transport; (b) a private `CreateProcessW` wrapper in this module (about 250 lines of unsafe: command line, environment block, handle list, pipe creation for tokio). **Recommend (a)** now and (b) if a source check or a hang finds an inheritable handle.
- **OQ-C: credential copies on Windows.** tokio's Windows child pipes copy through `Blocking` buffers (up to its internal buffer size) that are neither ours nor wiped; the Unix path has no such copy. This is the "dependency copies" class that TR1.8 §4 asks to account for honestly. Options: (a) accept and record it; (b) own overlapped pipe I/O with wiped buffers (about 300 lines of unsafe; tokio's named-pipe types copy too, so it would be a direct `ReadFile` loop). **Recommend (a)** for 1.1.0.
- **OQ-D: `CREATE_NO_WINDOW` and `DIE_ON_UNHANDLED_EXCEPTION`.** They keep a console from flashing from a GUI host and a crash from waiting on a dialog. They are changes from "whatever the OS defaults to". **Recommend keeping both.**
- **OQ-E: the interim neutral directory.** Drafted as the snapshot's `SystemRoot`; step 4.3 owns the snapshot (`endpoint_environment.rs:75-83`) and must capture it. Alternatives: `GetSystemDirectoryW`, or a private empty directory. **Recommend** 4.3 decide; 4.2 keeps the refusal so that nothing runs in an unintended directory.
- **OQ-F: a job that cannot be nested.** If assignment to the new job is denied (an outer job that forbids nesting) the helper is refused (`SpawnFailed`, an `Unavailable` error), never run uncontained. It was not observable on dabeest. **Recommend refuse.**
- **OQ-G: no spawn-time size bound on Windows (section 5).** **Recommend** none; the view's own limit holds.
