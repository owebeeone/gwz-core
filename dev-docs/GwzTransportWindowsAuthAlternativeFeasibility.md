# Windows authentication alternative feasibility — 2026-10-03

**Finding:** `sspi` 0.23.0 offers a real independent Rust Kerberos/NTLM/Negotiate implementation with caller-owned asynchronous network waits. A bounded native Windows probe demonstrated cancellation of an actual suspended Kerberos network request and release of its socket/operation slot. It is **not a drop-in replacement for the draft Windows authentication policy**: outbound credentials are mandatory, current-logon SSO is absent from the tested independent API, Digest is absent, and discovery, secret handling and EPA interoperability still require review. No product GO or policy change follows from this run.

## Exact implementation and limits

Crate source archive SHA-256 `256b74a75c961d4eb11e0e302a4451cdc51d713d5f26b2ede8156ba61cca5d7e`, VCS `b21f4581a880cfb5eb096d95c64d0dcea5229158`. Selected source bytes and hashes are retained under `primary-source/` and `primary-source-manifest.json`.

- **Independent implementation:** concrete `Ntlm`, `Kerberos`, `Negotiate` types execute Rust protocol code. [`generator.rs`](https://github.com/Devolutions/sspi-rs/blob/b21f4581a880cfb5eb096d95c64d0dcea5229158/src/generator.rs) owns a boxed future; `start`/`resume` synchronously poll one step. `NetworkRequest` owns URL/protocol/data; `resolve_with_async_client` awaits caller `send`. Kerberos `send_to` suspends for TCP, UDP and KDC proxy HTTP(S). NTLM does not yield third-party I/O; the application owns peer token transport. A wrapper calling the same native `InitializeSecurityContext` would not establish these cancellation properties.
- **Cancellation and ownership:** probe encloses context, credential handle, tokens, generator and permit in the cancelled future, plus an async Tokio socket. Dropping that entire operation releases their Rust ownership and the socket. Merely dropping a borrowed `resolve_with_async_client` future can leave the generator/context/credentials alive in its caller. Do not resume a cancelled authentication state; abandon the whole exchange and any associated peer connection.
- **Synchronous work remains:** generator polling includes parsing, crypto and other synchronous work; Tokio timeout cannot interrupt such a poll. [`network_client.rs`](https://github.com/Devolutions/sspi-rs/blob/b21f4581a880cfb5eb096d95c64d0dcea5229158/src/network_client.rs) default optional backend is blocking TCP/UDP/reqwest, not the tested async adapter. Windows [`dns.rs`](https://github.com/Devolutions/sspi-rs/blob/b21f4581a880cfb5eb096d95c64d0dcea5229158/src/dns.rs) directly calls synchronous `DnsQuery_W`; system registry discovery and cross-realm referral discovery occur outside yielded I/O. Explicit initial KDC configuration avoids initial discovery in this probe, not every referral. These paths need bounded discovery/CPU handling. `AsyncNetworkClient::send` returns a future without `Send`; direct use needs a local task or a differently designed generator pump.
- **Identity gap:** NTLM, Kerberos and Negotiate outbound acquisition explicitly reject missing auth data. Kerberos accepts explicit password credentials or explicitly supplied keytab key; optional smart-card support exists. No independent current-logon Windows ticket/key acquisition API was established. The stale library documentation referring to `sspi::winapi` is not evidence of such an API in this pinned source. Password success cannot substitute for NULL-current-logon identity behavior. [`auth_identity.rs`](https://github.com/Devolutions/sspi-rs/blob/b21f4581a880cfb5eb096d95c64d0dcea5229158/src/auth_identity.rs)
- **Secrets:** `Secret<T>` uses `ZeroizeOnDrop`, and password handles use it. However, [`kerberos/client/mod.rs`](https://github.com/Devolutions/sspi-rs/blob/b21f4581a880cfb5eb096d95c64d0dcea5229158/src/kerberos/client/mod.rs) converts the password to an ordinary `String`, borrows it through `as_exchange(...).await`, then uses it after that await. This copy lacks a zeroizing wrapper. Tokens/network buffers are ordinary `Vec<u8>`. Cleanup ownership was demonstrated; complete secret erasure was not. Review clone/temp-buffer/debug/tracing behavior before admission.
- **Negotiation and binding:** SPNEGO Kerberos/NTLM and additional PKU2U code exist. Negotiate has library-defined Kerberos-to-NTLM fallback for time skew, authority, certificate and unknown-credential errors; this must be reconciled with GWZ's accepted policy. NTLM consumes `BufferType::ChannelBindings` or `set_channel_bindings`, hashing application data into AV pairs; Kerberos has RFC 4121 checksum/CBT code. NTLM's acceptor only checks mismatch when a client binding AV pair exists, and authenticate-target-info source does not add a service-principal AV pair. Therefore present-binding mismatch success does not establish mandatory-binding/service-binding/full EPA parity. [`NTLM computation source`](https://github.com/Devolutions/sspi-rs/blob/b21f4581a880cfb5eb096d95c64d0dcea5229158/src/ntlm/messages/computations.rs)
- **Digest:** there is no independent WDigest/Digest provider in this pin's package enumeration or implementations. Crypto `Digest` trait names are unrelated. It cannot answer the current WDigest helper-only parity requirement. [`lib.rs`](https://github.com/Devolutions/sspi-rs/blob/b21f4581a880cfb5eb096d95c64d0dcea5229158/src/lib.rs)

## Cost, failures and recommendation

Candidate license is MIT OR Apache-2.0; MSRV 1.93. Windows tree contains 155 unique packages including the probe (154 external), despite disabling default features. This is the probe closure, not incremental additions to GWZ. Crypto dependencies include `picky 7.0.0-rc.26`, `rsa 0.10.0-rc.18` and `pkcs1 0.8.0-rc.4`; `dependency-summary.json` retains package/license/repository metadata. Optional network client/TLS/smart-card features add cost and were disabled. This probe does not propose replacing the separately qualified native TLS approach.

Initial build failed because allowed `picky-krb 0.12.5` adds `GssApiMessageError::InvalidMechanismOid`, making `sspi 0.23.0`'s match nonexhaustive. Pinning 0.12.4, exactly the candidate's published lockfile version, repaired it without source modification. First probe failed because the runner omitted `complete_auth_token` after `CompleteNeeded`; corrected runner then passed. Both failures, earlier sources and lockfile remain retained. A failed SFTP path attempt is also recorded.

**Recommendation:** retain the native SSPI isolated-worker approach for the accepted current-logon/default-identity contract and OS provider behavior. This candidate is plausible only for a separately reviewed explicit-credential subset where caller-owned network cancellation has value. Admission would require credential-policy and fallback decisions, zeroizing temporary-secret fixes/review, bounded discovery/CPU and async-task integration, native SSPI/KDC/HTTP interoperability and strict EPA qualification, and dependency/license/security review. A native worker still retains ownership/capacity until a running native call returns; this experiment does not prove provider-call abort. An absolute stop guarantee during arbitrary synchronous work would require additional isolation, which was not investigated. No public draft, policy, Git mutations, trust store, service, account, hosts, zone or shared proxy settings changed.

Inventory collection limitation: the final inventory replaced an earlier download-only stderr (635 bytes) before collection. Its recorded hash and the explicit loss are documented in the run README; neither build nor probe results were overwritten.
